Learn Your Own Skills Library with Phoebe

A skill is a reusable instruction your AI assistant loads when a request matches it. One skill is a prompt. Twenty skills are a library, and a library has library problems: the assistant has to find the right one, two skills fight over one request, descriptions drift away from what the skill does, and every skill costs context. Six sessions around one question: for each request you send, does it reach the right skill, and what does keeping that true cost?

The six sessions 🎯 · from a pile of prompts to a library someone keeps

The running case is Pemberton & Thistle (constructed), a four-person research consultancy that writes client briefs, market scans and workshop packs. The firm is invented, and so is its skills library; it grows one piece per session, from a list of repeated work to a quarterly library review. The patterns are vendor-neutral: the shared skill format, then where Anthropic, OpenAI and GitHub implement it, read from their own docs.

🗂️ Session 1 · foundations

When repeated work deserves a skill

The three-times rule and its cost side; skill, template, automation or just asking; what a skill is made of; why only names and descriptions load up front. Build-along: inventory a week of repeated work and pick the first three skills.

▶ Start here 🔎 Session 2 · foundations

A description the assistant can find

The description is the router's only evidence: what the skill does and when to use it, the phrases people really type, "do not use for" lines, a naming scheme. Build-along: rewrite four vague descriptions and test them live.

findable 🧱 Session 3 · core

One job, clear inputs, a built-in check

The body of a skill: purpose, the inputs to ask for, steps, an output format, a self-check before returning, and references kept out of the main file until needed. Build-along: split one bloated skill into a main file and a reference.

well built 🧭 Session 4 · bench night

The skill-routing bench

Sixty requests routed live across a library of descriptions: right skill, wrong skill, no skill, fired when nothing should. Climb the ladder, try keyword stuffing, then add a near-duplicate skill and watch the twins fight.

★ the bench 🧪 Session 5 · stretch

Testing a skill like code

Trigger tests that should and should not fire, near-misses, a held-out set, golden-output checks, and a regression run after every edit. Build-along: a twelve-case trigger test set for one skill.

tested 🧹 Session 6 · capstone

Upkeep: overlap, drift, token cost, retirement

Overlap audits, description drift, what a growing library costs in context, merging, retiring with a pointer left behind, and an owner per skill. Capstone: Pemberton & Thistle's quarterly library review, scored on the bench.

What is honest here 🧾

The bench computes for real; the router is a labelled stand-in for a language model; the running case is constructed; the docs are read at their source.
