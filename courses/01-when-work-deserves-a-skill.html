When repeated work deserves a skill

Everyone who uses an AI assistant every day ends up typing the same paragraph of context again and again: the house style, the sections a brief needs, the checks before anything goes to a client. A skill packages that paragraph so the assistant loads it when a request matches. Tonight we decide which repeated work deserves one, which does not, and what a skill is made of.

Part 1 · covers the three-times rule and its cost side

Three times, then count the cost

5 min live

The signal that work deserves a skill is not "this is important". It is "I have explained this context before". Anthropic's skill authoring guide puts the habit plainly: work through a task with the assistant, notice what information you repeatedly provide, and package that. A working rule of thumb is three times: once is a request, twice is a coincidence, the third time you are re-typing a procedure. The rule is a habit, not a published threshold, and it has a cost side that most people skip.

LiveWhat the third repeat tells you3 min▶

The first time you ask for a client brief, the context you type is the brief: who the client is, what they want. The second time, you notice you typed the same three paragraphs about structure and tone. The third time, you are maintaining a procedure in your head and pasting it by hand, and each paste is slightly different.

That third paste is the signal. What you keep re-typing is not the task but the way you do the task: the sections a brief always has, the questions you always ask the client, the check you always run before it goes out. That is exactly what a skill holds.

Count honestly. A request that recurs but needs new context every time ("summarise this article") is not a skill, however often you send it: there is nothing stable to package.

LiveThe cost side: four lines on the bill2 min▶
CostWhen you pay it
Writing and testing the skillOnce, then again after every edit (session 5)
The description in contextEvery session, whether or not the skill fires. The open specification budgets about 100 tokens per skill for name and description
Routing riskEvery new skill is one more candidate for every request; it can steal requests from a neighbour (session 4)
UpkeepWhenever the way you work changes and the skill does not (session 6)

The first two are small for one skill. They stop being small at forty. Claude Code caps the whole listing of skill descriptions at about 1% of the model's context window and starts dropping descriptions when it overflows; Codex caps its list at 2% of the window (8,000 characters when the window size is unknown) and shortens descriptions first. A library has a budget whether you plan one or not.

Self-studyStart with evaluation, not with writing2 min▶

Anthropic's guidance for skill authors says to build evaluations before writing extensive documentation: run the assistant on representative tasks without a skill, write down where it fails, then write just enough to fix those failures. If the assistant already produces a good brief from a one-line request, the skill has nothing to add, and the three-times rule should not overrule that evidence. Session 5 turns this into a habit.

Real world

Why the format exists at all. Anthropic's engineering team introduced Agent Skills in October 2025 as "organized folders of instructions, scripts, and resources that agents can discover and load dynamically", then published the format as an open standard. The open specification now says it was "originally developed by Anthropic" and adopted by a growing number of agent products; OpenAI's Codex and GitHub Copilot both document the same SKILL.md folder shape. The problem they all solve is the one above: context people kept pasting by hand.

Part 2 · covers skill against template, automation and just asking

Skill, template, automation, or just ask

5 min live

Repeated work has four homes, and a skill is only one of them. The question that separates them is where the judgment lives. If nothing needs judging, a machine can run it without you: that is an automation. If only the shape repeats and you fill it in yourself, it is a template. If it is a one-off, say it in chat. A skill earns its place when the steps repeat but each run still needs the assistant's judgment on new material.

Automations and no-code tools have their own course: Learn Automation. Personal routines such as triage and follow-ups are in Learn AI Productivity.

Self-studySkills that call automations, and the reverse2 min▶

The homes combine. A skill can bundle a script for the deterministic part, and the official docs encourage it: Anthropic's overview notes that when a skill runs a script, only the script's output enters the context, never its code. The split to aim for is judgment in the instructions, determinism in the script. Session 3 builds one.

The reverse also happens: something that started as a skill turns out to need no judgment at all. That is a retirement candidate (session 6), not a skill to polish.

Real world

Not every match needs a skill. The open format's own guide on descriptions notes that agents usually consult skills only for work beyond what they can do alone: a simple one-step request like "read this PDF" may not trigger a PDF skill even when the description matches perfectly. A skill that packages something the assistant already does well is a description you pay for in every session and rarely use.

Part 3 · covers the anatomy of a skill and progressive disclosure

A folder, a description, and three levels of loading

5 min live

Across vendors the shape is the same. A skill is a folder whose required file, SKILL.md, starts with two fields, a name and a description, followed by instructions; it may carry scripts/, references/ and assets/. What makes a library possible is that these parts load at different times. The open specification calls it progressive disclosure.

LiveThe two required fields3 min▶

The open Agent Skills specification requires exactly two frontmatter fields. name: 1 to 64 characters, lowercase letters, numbers and hyphens, no leading, trailing or double hyphen, and it must match the folder's name. description: 1 to 1,024 characters, saying what the skill does and when to use it. Anthropic adds that neither may contain XML tags and the name may not contain the reserved words "anthropic" or "claude".

★ A minimal SKILL.md (constructed Pemberton & Thistle example)--- name: client-brief description: Drafts a two-page client project brief from intake notes: objectives, scope, deliverables, timeline and open questions. Use when a new engagement starts and someone asks for a project brief, a scoping brief or a brief for the client. --- # Client brief 1. Ask for the intake notes and the client's name if they are missing. 2. ...
LiveProgressive disclosure, three levels2 min▶

Anthropic's overview gives the numbers: Level 1 metadata loads at startup, about 100 tokens per skill; Level 2, the body, loads when the skill is triggered and should stay under 5,000 tokens; Level 3 files cost nothing until read, and a script's code never enters the context, only its output. Codex works the same way: it starts with each skill's name, description and file path, and reads the full SKILL.md only when it decides to use the skill. The consequence for a library is direct: twenty skills cost twenty descriptions in every session, and nothing else until they fire.

Real world

A skill is software you install. Anthropic's overview warns to use skills only from trusted sources, because a skill can direct the assistant to call tools or run code that does not match its stated purpose, and recommends auditing every bundled file before use. A library you build yourself is the safe default; a skill copied from a stranger's repository deserves the same review as any script you would run.

Build-along

Sort a week of repeated work

★ 22 min · everyone builds

Pemberton & Thistle (Constructed Pemberton & Thistle example) kept a log of everything they asked their assistant for in one week. Below is what repeated. You will place each item on two axes, how often it comes back and how much judgment each run needs, then choose the first three skills. Your own week will look different; the method is the point.

Read the week's log. These are the repeated requests from one week at the firm (constructed). Next to each, write two things: how many times a month it comes back, and what you would have to re-explain each time.

★ Step 1 · Pemberton & Thistle, one week of repeated asks (constructed)client brief from intake notes 4 / month re-explain: sections, tone, open questions market scan of a sector 3 / month re-explain: sources we trust, sizing method meeting minutes with actions 12 / month re-explain: owner + date on every action workshop pack for a client team 2 / month re-explain: timing grid, facilitator notes invoice reminder emails 6 / month re-explain: nothing, same three wordings weekly timesheet totals 4 / month re-explain: nothing, same sums monthly newsletter 1 / month re-explain: the section order onboarding plan for a new associate rare re-explain: the checklist ad hoc questions varied re-explain: nothing, never the same twice

Run each item through the tree in Part 2. Ask the first question honestly: does any run need judgment? Invoice reminders and timesheet totals do not; they are automations. The newsletter and the onboarding plan repeat as a shape; they are templates for now.

Rank what is left. Four candidates sit in the skill corner. Multiply times per month by minutes of re-explaining saved per run, then subtract what you know about the cost side: a skill that will collide with a neighbour, or one the assistant already does well without help, ranks lower.

★ Step 3 · the ranking, in the firm's own wordsCANDIDATE PER MONTH SAVED EACH RUN NOTE meeting minutes 12 5 min high volume, clear output client brief 4 15 min the firm's signature document market scan 3 15 min sources and method vary by analyst workshop pack 2 20 min rare; wait for the third client (minutes are constructed estimates; your numbers will differ)

Choose the first three and name them. Pemberton & Thistle choose client-brief, market-scan and meeting-minutes. Names follow one scheme (noun-phrase, lowercase, hyphens), because the spec requires the characters and a library needs the consistency. The workshop pack waits until it has come back a third time.

Write the inventory page. One line per item: its home, the reason, and for the three skills a one-sentence purpose. Session 2 turns those sentences into descriptions the assistant can find.

★ Step 5 · Pemberton & Thistle's library, page one (constructed)SKILLS (3) client-brief, market-scan, meeting-minutes AUTOMATIONS invoice reminders, timesheet totals TEMPLATES monthly newsletter, onboarding plan JUST ASK ad hoc questions WAITING workshop-pack (2 uses so far; revisit at the third) Budget note: 3 descriptions in every session; each one must earn it.

Keep the waiting list. The items you did not turn into skills are as useful as the ones you did. When one of them comes back a third time with the same context, it graduates, and the decision is quick because the reasoning is already written down.

Homework

Before session 2

30 min
  1. Log one week of your own repeated asks. Every time you paste the same context into an assistant, write down the task and what you pasted.
  2. Run each through the four homes. Automation, template, just ask or skill, with the one-line reason.
  3. Pick at most three skills and name them with one consistent scheme that passes the spec: lowercase, numbers and hyphens, 64 characters at most.
  4. Count your description budget. How many skills do you already have installed? Multiply by about 100 tokens: that is what loads in every session before you type anything.
Check yourself

Three questions

Clear all three and session 1 gets stamped in your passport.

1 · Pemberton & Thistle total their timesheets four times a month, the same sums every time. Why is that not a skill?

Frequency is necessary, not sufficient. Where the steps need no judgment, a trigger and an action are cheaper than an assistant reading instructions.

2 · A library has 30 skills installed and you send one request that matches one of them. What has loaded into the assistant's context?

Progressive disclosure: Level 1 for every skill always, Level 2 for the one that fires, Level 3 only on demand. That is why every description is a standing cost.

3 · Which of these names is valid under the open Agent Skills specification?

Lowercase letters, numbers and single hyphens, not at either end, and the name must match the parent folder.
